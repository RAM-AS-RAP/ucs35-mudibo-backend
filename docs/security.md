# Security controls

This page summarises how the AgriSence backend protects accounts, data and payments, where each control is implemented, and which limitations remain. It is also source material for the thesis. Paths are relative to the repository root.

## Controls

| Area | Control | Where |
| --- | --- | --- |
| Authentication | Passwords are hashed with Argon2id (`argon2-cffi` defaults); plain passwords are never stored or logged. Access tokens are HS256 JWTs signed with `JWT_SECRET` (at least 32 characters, checked at startup) and expire after `ACCESS_TOKEN_EXPIRE_MINUTES` (60). | `app/core/security.py`, `app/core/config.py` |
| Login failures | One generic 401 `invalid_credentials` for an unknown user, a wrong password and a disabled account. Login is throttled per IP (slowapi) and per identifier (`LOGIN_MAX_FAILURES` in `LOGIN_FAILURE_WINDOW_MINUTES`). | `app/services/auth_service.py`, `app/routers/auth.py` |
| Password policy | 8 to 128 characters with upper case, lower case, digit and symbol at registration. New passwords (change, invite, reset) are also checked against the account's name, email and phone and a common-password list, and admins need at least 12 characters. | `app/core/password_policy.py`, `app/schemas/auth.py` |
| Role checks from the database | Every request reloads the user from PostgreSQL; the role and the super admin flag come from the row, never from the token or the client. `require_role`, `require_admin` and `require_super_admin` guard each route. `tests/route_matrix.py` lists every route and its roles, and a test proves every other role gets 401/403 before validation or database access. | `app/core/dependencies.py`, `tests/route_matrix.py`, `tests/test_route_inventory.py` |
| Disabled accounts | A disabled account's next request gets 401; its listings are hidden from buyers; users are disabled, never deleted (database trigger). | `app/core/dependencies.py`, `app/services/listing_service.py`, `users_prevent_delete` trigger |
| Token revocation after a password change | Every password change sets `password_changed_at` from the database clock, and tokens issued before that second are refused. Accounts flagged `must_change_password` can only change the password. | `app/core/dependencies.py`, `app/services/auth_service.py` |
| Rate limits | Per-IP limits on registration, login, code routes, checkout, payment, admin writes (slowapi, in memory). 429 responses use the uniform body with `Retry-After`. `RATE_LIMITS_DISABLED` exists for development and is refused in production. | `app/routers/*`, `app/main.py`, `app/core/config.py` |
| Request validation | Pydantic schemas with `extra="forbid"`, so a client cannot send a role, a status, a price or a total. Multipart forms reject unknown fields. Validation errors list field names and safe messages and never echo passwords, codes or tokens. | `app/schemas/*`, `app/core/errors.py` |
| Body limits | JSON and form bodies are limited to `MAX_JSON_BODY_BYTES` (64 KiB), the multipart listing routes to `MAX_IMAGE_BYTES` + 64 KiB, and the Daraja callback to `CALLBACK_MAX_BYTES`. `Content-Length` is checked and reading stops at the limit (413). | `app/core/middleware.py`, `app/routers/payments.py` |
| Host check | `TrustedHostMiddleware` with `ALLOWED_HOSTS` (explicit host names required in production). | `app/main.py`, `app/core/config.py` |
| CORS | Exact origins from `CORS_ORIGINS` (validated as bare http(s) origins, no wildcard in production), no credentials, a fixed list of methods and headers. | `app/main.py`, `app/core/config.py` |
| Response headers | `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, and HSTS in production. Interactive docs are disabled in production. | `app/core/middleware.py`, `app/main.py` |
| Error handling | Uniform error body with a request id. Unhandled errors return a generic 500 and the traceback goes only to the log. Database errors map to 503 (`service_unavailable`, `busy`) or 500, never with driver text or SQL. | `app/core/errors.py`, `app/core/middleware.py` |
| Database timeouts | `SET LOCAL statement_timeout` and `lock_timeout` at the start of every transaction bound slow queries and lock waits. | `app/db.py` |
| Secrets handling | Secrets come only from the environment or `.env` (git-ignored). `scripts/check_config.py` reports on settings without printing values. CI uses no secrets. A source scan fails on secret-looking literals. | `app/core/config.py`, `.gitignore`, `scripts/check_config.py`, `tests/test_source_security.py` |
| Log redaction | A filter on every log handler masks values of keys such as `password`, `token`, `authorization`, `api-key`, `secret`, `passkey` and `code`, any `Bearer` value and the Daraja callback token, and reduces phone numbers to their last 3 digits. Daraja payloads are redacted before they are stored. Access logs never include query strings. | `app/core/logging_config.py`, `app/integrations/daraja.py`, `app/main.py` |
| Safe code patterns | Raw SQL uses bound parameters only. A test fails on formatted SQL in `text()`, `eval`/`exec`, `pickle`, unsafe YAML, `subprocess`, disabled TLS verification, `print` in `app/`, float money, ML libraries and production Daraja URLs. | `tests/test_source_security.py` |
| Payment integrity: totals | The server computes `total_amount = ceil(quantity × unit price)` from the listing row it locks (`FOR UPDATE`). The client never sends an amount, a price or a phone number. | `app/services/order_service.py`, `app/services/payment_service.py` |
| Payment integrity: idempotency | `Idempotency-Key` is required and stored scoped to buyer and order. A replay returns the same result without a second STK prompt. A partial unique index allows only one open payment per order. | `app/services/payment_service.py`, migration `20261008000600_payments.sql` |
| Payment integrity: callback | The callback URL carries a secret token (at least 24 URL-safe characters, compared in constant time). A wrong token gets an empty 404. Every callback is stored as an append-only event first. The amount must match the order total, and the masked phone in the callback is never used. A mismatch or late success is flagged `needs_reconciliation` for an admin instead of paying the order. | `app/routers/payments.py`, `app/services/payment_service.py` |
| Sandbox only | Settings and the Daraja client accept only the sandbox environment, URL and shortcode, and no setting selects production. | `app/core/config.py`, `app/integrations/daraja.py` |
| Database constraints and triggers | CHECK constraints and triggers enforce immutable roles, super admin protection, frozen order snapshots, the payment state graph, append-only payment events, listing status vs. quantity, and invite and reset code rules. | `supabase/migrations/*`, `docs/schema.md` |
| Row level security | RLS is enabled on every table. The Data API roles `anon` and `authenticated` have no privileges or policies, so the Supabase REST API exposes nothing. The backend connects as the owner and enforces ownership in service code. | `supabase/migrations/20261008000800_security_rls_and_storage.sql` |
| Least-privilege pipeline role | The ML pipeline's `pipeline_writer` login can only select, insert and update specific columns of `market_locations`, `market_prices` and `forecasts`. | `supabase/migrations/20261010000100_pipeline_writer_role.sql` |
| Image handling | Only JPEG and PNG are accepted, with signatures checked. Every image is decoded, resized to at most `IMAGE_MAX_DIMENSION` and re-encoded as JPEG without metadata (EXIF, GPS) before storage. Storage paths are random and never exposed. | `app/utils/images.py`, `app/services/listing_service.py` |
| Email code protections | Invite and reset codes are random 8-character codes. Only an HMAC (keyed by `INVITE_CODE_PEPPER` and bound to purpose and record) is stored. Codes are short-lived, single use and locked after a total attempt cap, and each attempt is committed before the check. All failures return one generic 400, and the request routes always return the same 202. Codes are never put in URLs, subjects, responses or logs. | `app/core/codes.py`, `app/services/invite_service.py`, `app/services/password_reset_service.py` |
| Admin powers | Only the super admin invites, disables or enables admins. The super admin cannot be disabled or demoted. No route returns a credential. | `app/services/admin_user_service.py`, `app/services/invite_service.py` |

## Known limitations

- Rate limits live in process memory: they reset on restart and are not shared between instances, so the API must run as a single instance.
- Phone numbers are never verified, and neither are farmer and buyer emails. Anyone can register with a number they do not own.
- There is no multi-factor authentication, including for administrators.
- Payments run only in the Safaricom sandbox. No real money moves, and there are no refunds (a voided sale is settled outside the platform).
- Access tokens are stateless. Apart from the password change rule and the per-request disabled check, a token cannot be revoked before it expires (60 minutes), and there is no logout on the server.
- Uploaded images are re-encoded but not scanned for malware.
- The Supabase free plan has no point-in-time recovery. Backups are manual logical dumps (see [backup.md](backup.md)).
- Farmers and buyers without an email address cannot reset a forgotten password by themselves.
- Statement and lock timeouts depend on `SET LOCAL` working through the transaction pooler; if they ever conflict they can be turned off (`0`), which removes that protection.
